O que você vai construir

Este projeto é um Diagnóstico Socioambiental Participativo (DSAP) da Vila dos Coqueiros — uma comunidade pesqueira fictícia. Cada fala de morador, notícia ou relatório técnico vira um fator classificado na matriz SWOT e ponderado por importância. O resultado é uma escala de sustentabilidade de 0 a 10 que sintetiza o estado da comunidade.

"Os fatores favoráveis (forças + oportunidades) superam os desfavoráveis (fraquezas + ameaças) — e em que grau?"

Você partirá de 4 arquivos de texto e chegará a tabelas, uma escala-velocímetro de sustentabilidade e, opcionalmente, um dataset para treinar uma IA codificadora.

A matriz SWOT deste diagnóstico
Interno ·Forças (fo)Pesca artesanal · Patrimônio cultural
Externo ·Oportunidades (op)Turismo comunitário
Interno ·Fraquezas (fr)Saneamento · Descarte de resíduos
Externo ·Ameaças (am)Assoreamento da foz
Comece pelo essencial: passos 1 → 2 → 3 já entregam as tabelas do diagnóstico. O passo 5 calcula a escala — o coração analítico do método.

📖 Vocabulário mínimo — leia uma vez
ITEM
Uma unidade de análise: um trecho codificado (citação + resumo + fator + SWOT + importância).
fator
A palavra-chave temática do trecho (ex.: Pesca_Artesanal). Todo fator tem um bloco ONTOLOGY.
SWOT
Classifica o fator: fo força, fr fraqueza (internos) · op oportunidade, am ameaça (externos).
importância
Peso do fator na escala: 0 baixo · 0.5 moderado · 1 alto.
dimensão
A esfera da sustentabilidade do fator: ambiental · sociocultural · econômica · governamental.

01 Verificar o projeto Confirme que os arquivos compilam sem erros antes de exportar. Essencial ⏱ ~2 min
Objetivo: garantir que os 4 arquivos estão íntegros. Tudo depois disto assume um projeto sem erros — começar aqui evita horas de depuração adiante.
Comando
# A partir da pasta do projeto: cd case-studies/Socioenvironmental/DSAP_Vila_dos_Coqueiros synesis check project.synp
Saída esperada: ✓ No errors found. — zero ERROs. Avisos não bloqueiam a compilação mas devem ser investigados.
Pronto quando: o terminal mostra No errors found. Se aparecer um código E0xx, veja a faixa de Solução de problemas no rodapé antes de seguir.
Estrutura do projeto
project.synpPonto de entrada: declara template, bibliography, annotations, ontology
template.syntDefine campos, tipos e GUIDELINES de SOURCE, ITEM e ONTOLOGY
references.bib3 fontes: oficina comunitária, jornal e relatório técnico
annotations.syn3 SOURCEs e 6 ITEMs com citação, resumo, fator, SWOT e importância
ontology.syno6 fatores, cada um com descrição e dimensão de sustentabilidade
Erros comuns: fator usado sem bloco ONTOLOGY (E004), campo REQUIRED ausente como importância (E020), valor SWOT fora do enumerado (E031). synesis check lista todos com número e local exato.
02 Compilar → JSON Gera o artefato canônico v3.0 com todo o diagnóstico serializado. Essencial ⏱ ~3 min
Objetivo: produzir o único arquivo do qual todos os outros formatos derivam. Pense nele como o "negativo" da foto — gere uma vez, revele em vários formatos depois.
Comando
synesis compile project.synp --json exports/dsap_vila_dos_coqueiros.json
Estrutura do JSON gerado
{ "version": "3.0", "export_metadata": { "item_count": 6, "source_count": 3, "concept_count": 6, "chain_count": 0 }, "corpus": [ ... ITEMs com fator, swot, importância ... ], "ontology": [ ... 6 fatores com dimensão ... ] }
Sem cadeias: este método não usa CHAIN (chain_count: 0). A análise é por fator e SWOT, não por relação causal.
Verificação rápida

Pronto quando: o arquivo exports/dsap_vila_dos_coqueiros.json existe e imprime item_count: 6, source_count: 3, concept_count: 6.

04 Exportar Alpaca JSONL Dataset de fine-tuning derivado dos dados validados pelo compilador. Análise ⏱ ~5 min
Objetivo: empacotar seu trabalho de codificação como exemplos de treino, para que uma IA aprenda a interpretar novos trechos do seu jeito. Opcional — pule se não vai treinar modelos.
Comando
synesis compile project.synp --alpaca exports/dsap_vila_alpaca.jsonl
Estrutura de cada linha JSONL
{ "instruction": "Provide an analytical interpretation of the passage below. (Memo analítico explicando a interpretação)", "input": "\"A pesca artesanal aqui sustenta mais da metade das famílias. Meu avô já pescava nesse mesmo canto, meu pai também.\"", "output": "A pesca artesanal é a principal atividade econômica da comunidade, com continuidade intergeracional que reforça tanto a economia local quanto a identidade cultural." }
Como interpretar o formato Alpaca
CampoConteúdo
instructionTarefa derivada do DESCRIPTION do campo-alvo (aqui o MEMO resumo) — explica o que produzir
inputValor do campo QUOTATION (a citação da fonte)
outputValor do campo MEMO (o resumo analítico) — a resposta esperada do modelo
Neste template, o par instruction/input/output liga citação → resumo. Os campos fator, swot e importância são classificações estruturais, não entram no output textual.
Para que serve: cada linha treina um LLM a escrever o memo analítico no estilo do pesquisador — dada uma fala nova, o modelo aprende a explicar o mecanismo socioambiental por trás dela.
Inspecionar o arquivo gerado
# Contar pares e ver o primeiro: python -c "import json; L=[json.loads(l) for l in open('exports/dsap_vila_alpaca.jsonl', encoding='utf-8')]; print(len(L),'pares Alpaca'); print(json.dumps(L[0], indent=2, ensure_ascii=False))"
Pronto quando: o script imprime 6 pares Alpaca e mostra um par com instruction, input e output preenchidos.
05 Escala de sustentabilidade Calcula e visualiza a escala 0–10 do diagnóstico no notebook. Análise ⏱ ~15 min
Objetivo: ver o diagnóstico virar um número e um velocímetro — a síntese que responde à pergunta lá do topo: a comunidade pende para o favorável ou o desfavorável?
Abrir o notebook
# No VS Code: abra escala_sustentabilidade.ipynb # Ou via Jupyter: jupyter notebook escala_sustentabilidade.ipynb
A fórmula da escala
# F=Força O=Oportunidade Fr=Fraqueza A=Ameaça # (soma das importâncias de cada grupo) escala = ((F+O) - (Fr+A)) / ((F+O) + (Fr+A)) * 5 + 5
O notebook usa synesis.load() — compila em memória, sem export intermediário. A pasta do projeto é detectada automaticamente.

4. VisualizarVelocímetro semicircular da escala 0–10

06 Synesis-Coder Codificação assistida por LLM: anota novas fontes seguindo o template do projeto. Avançado ⏱ ~10 min
Objetivo: acelerar a codificação de novas fontes — a IA lê o template (com as GUIDELINES de SWOT, dimensão e importância) e propõe blocos ITEM que você revisa, em vez de escrever do zero.
Pré-requisito: chave da API
# Opção A — variável de sessão (PowerShell): $env:ANTHROPIC_API_KEY = "sk-ant-..." # Opção B — arquivo .env (recomendado, persiste): ANTHROPIC_API_KEY=sk-ant-... SYNESIS_CODER_MODEL=claude-sonnet-4-6 SYNESIS_CODER_LANGUAGE=pt-BR
Onde colocar o .env: na pasta do projeto (case-studies/Socioenvironmental/DSAP_Vila_dos_Coqueiros/) ou em qualquer pasta-pai de onde você roda o comando — o Coder procura no diretório atual e sobe a árvore. Use o .env.example de synesis-coder/ como modelo. Nunca versione o .env.
Codificar um trecho único
# item: anota um trecho de fonte diretamente synesis-coder item --project project.synp --bibref oficina_coqueiros2026 --text "Os jovens estão indo embora porque não há emprego além da pesca." --language pt-BR
O Coder lê o template.synt (incluindo GUIDELINES) e gera um bloco ITEM completo — com fator, swot e importância sugeridos — para você revisar e colar em annotations.syn.
Outros subcomandos relevantes
SubcomandoUso neste projeto
document Codifica uma transcrição inteira de oficina ou entrevista e gera um .syn completo
ontology Lê as anotações e sugere blocos ONTOLOGY (com dimensão) para fatores ainda não definidos

Codificar transcrição completa (document)
synesis-coder document --project project.synp --bibref oficina2_coqueiros --input oficinas/oficina2.txt --output oficinas/oficina2.syn --language pt-BR
Expandir ontologia (ontology)
synesis-coder ontology --project project.synp --output ontology_sugestoes.syno --language pt-BR
Fluxo recomendado: document → critique → normalize → incorporate → synesis check. Nunca incorpore sem verificar. Depois, recalcule a escala no passo 5.

🛟 Solução de problemas — os tropeços mais comuns
command not found: synesis O pacote não está instalado ou o ambiente virtual não está ativo. Rode pip install synesis e confirme com synesis --version.
E004 — código não definido Um ITEM usa um fator que não existe em ontology.syno. Adicione o bloco ONTOLOGY (ou use o Coder ontology no passo 6).
E020 — campo REQUIRED ausente Um ITEM está sem um campo obrigatório (citação, resumo, fator, swot, importância). O erro aponta arquivo e linha.
E031 — valor fora do enumerado O swot deve ser fo/fr/op/am e a dimensão uma das quatro definidas. Confira a grafia exata.
importância rejeitada O campo é SCALE em [0..1.01] — use apenas 0, 0.5 ou 1, conforme as GUIDELINES.
KeyError: 'code' (no notebook) A coluna de conceito da tabela ontologies chama-se fator, não code. Use set_index("fator").
ValueError: a escala exige importância > 0 Todos os fatores ficaram com importância 0 (denominador zero). Atribua 0.5 ou 1 a pelo menos um fator.
Regra de ouro: a qualquer momento em dúvida, volte ao passo 1 — synesis check é seu paraquedas. Quase todo erro adiante começa como um aviso ignorado aqui.
