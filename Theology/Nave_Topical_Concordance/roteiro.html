O que você vai construir

O Nave's Topical Bible (Orville J. Nave, 1905) é uma concordância temática: organiza toda a Escritura por verbetes (tópicos), e a cada verbete associa as passagens bíblicas que o tratam. Este projeto Synesis transforma essa obra de domínio público em dados compiláveis e consultáveis.

"Dado um tema — AARON, GRAÇA, ORAÇÃO — quais passagens bíblicas o Escritura aborda, e sob que subtópicos?"

Você partirá de arquivos de texto organizados de A a Z e chegará a um JSON canônico, tabelas para análise e um dataset para treinar uma IA classificadora de passagens.

5.315verbetes
82.826itens (passagens)
26arquivos A–Z
Anatomia de um ITEM
ITEM @nave1905 passage: Exo 6:16-20 entry: AARON note: Lineage of END ITEM
Um verbete (entry) reúne muitos itens; cada item aponta uma passagem e, opcionalmente, um subtópico (note) e uma referência cruzada (xref) para outro verbete.
Comece pelo essencial: passos 1 → 2 → 3 entregam o projeto compilado e as tabelas. Os passos 4–5 são extensões.
⚙ Antes de começar — instale e confira
  • Python 3.10+ instalado (python --version)
  • Synesis: pip install synesis · teste com synesis --version
  • Para análise em Python (passo 3): pip install pandas
  • Para o Coder (passo 5, opcional): chave ANTHROPIC_API_KEY
  • Terminal aberto na pasta do projeto (onde está nave.synp)
📖 Vocabulário mínimo — leia uma vez
entry (verbete)
O tópico da concordância (ex.: AARON). É o campo CODE — todo verbete tem um bloco ONTOLOGY.
passage
A referência bíblica em formato USX (ex.: Exo 6:16-20).
note
Subtópico descritivo do verbete (ex.: "Lineage of", "Children of").
xref
Referência cruzada "See / Also called" para outro verbete relacionado.
ITEM
Uma ocorrência: a ligação de uma passagem a um verbete sob um subtópico.
● Trilha essencial · passos 1–3 Faça estes três e você tem o projeto compilado e as tabelas prontas. ~10 min no total.
01 Verificar o projeto Confirme que os 26 arquivos A–Z compilam sem erros antes de exportar. Essencial ⏱ ~2 min
Objetivo: garantir que todos os arquivos de anotação e a ontologia estão íntegros. Em um corpus de 82 mil itens, começar por aqui evita caçar um erro perdido no meio do alfabeto.
Comando
# A partir da pasta do projeto: cd case-studies/Theology/Nave_Topical_Concordance synesis check nave.synp
Saída esperada: ✓ No errors found. — zero ERROs. Este projeto emite alguns WARNINGs (verbetes com descrições idênticas) que não bloqueiam a compilação.
Pronto quando: o terminal mostra No errors found (avisos são aceitáveis). Se aparecer um E0xx, veja a Solução de problemas no rodapé.
Estrutura do projeto
nave.synpPonto de entrada: declara template, bibliografia, 26 arquivos de anotação e ontologia
nave.syntDefine os campos: entry (CODE), passage, note, xref, description
nave.bibFonte única: a obra de Nave (domínio público)
annotations/nave_A…Z.syn82.826 ITEMs distribuídos por inicial do verbete
nave.syno5.315 verbetes, cada um com sua descrição
Por que 26 arquivos? Dividir o corpus por inicial (A, B, …, Z) mantém cada arquivo gerenciável e facilita revisar ou versionar um trecho do alfabeto sem tocar no resto.
02 Compilar → JSON Gera o artefato canônico v3.0 com toda a concordância serializada. Essencial ⏱ ~3 min
Objetivo: produzir o único arquivo do qual todos os outros formatos derivam. Pense nele como o "negativo" da foto — gere uma vez, revele em vários formatos depois.
Comando
synesis compile nave.synp --json exports/nave.json
Estrutura do JSON gerado
{ "version": "3.0", "export_metadata": { "item_count": 82826, "concept_count": 5315, "source_count": 1, "chain_count": 0 }, "corpus": [ ... ITEMs com entry, passage, note, xref ... ], "ontology": [ ... 5315 verbetes com description ... ] }
Sem cadeias: a concordância é um índice tema↔passagem, não uma rede causal (chain_count: 0).
Verificação rápida
# Conferir contagens no JSON gerado: python -c "import json; d=json.load(open('exports/nave.json', encoding='utf-8')); print(d['export_metadata'])"
Pronto quando: o arquivo exports/nave.json existe e imprime item_count: 82826 e concept_count: 5315.
Também disponível via API Python

03 Exportar CSV e Excel Gera tabelas prontas para análise em Pandas, R ou planilhas. Essencial ⏱ ~5 min
Objetivo: obter tabelas que você abre no Pandas para perguntar à concordância — quais verbetes têm mais passagens, quais passagens aparecem em mais temas, quais verbetes se cruzam via xref.
Comandos
# CSV: uma pasta com várias tabelas synesis compile nave.synp --csv exports/csv/ # Excel: uma planilha com abas separadas synesis compile nave.synp --xls exports/nave.xlsx # Tudo numa única execução: synesis compile nave.synp --json exports/nave.json --csv exports/csv/ --xls exports/nave.xlsx
Excel e o limite de linhas: a tabela items tem 82.826 linhas — acima do limite do Excel por aba (1.048.576) está OK, mas planilhas grandes abrem devagar. Para análise séria, prefira CSV + Pandas.
Tabelas geradas e suas colunas
TabelaColunas principais
sourcesbibref, reference
itemsbibref, entry, passage, note, xref
ontologiesentry (= verbete), description
Atenção: na tabela ontologies, a coluna que identifica o verbete é entry (o campo CODE do template), não code. Use ontologia.set_index("entry") em Pandas.
Perguntas típicas em Pandas
tabelas = resultado.to_dataframes() itens = tabelas["items"] # Verbetes com mais passagens: itens["entry"].value_counts().head(10) # Passagens citadas por mais verbetes: itens.groupby("passage")["entry"].nunique().sort_values(ascending=False).head() # Rede de referências cruzadas (entry -> xref): itens.dropna(subset=["xref"])[["entry", "xref"]].drop_duplicates()
Pronto quando: a pasta exports/csv/ tem 3 arquivos (sources, items, ontologies) e items.csv tem 82.826 linhas. Trilha essencial concluída.
● Trilha de dataset · passo 4 Gere um dataset Alpaca para treinar uma IA a classificar passagens por tema. Opcional.
04 Exportar Alpaca JSONL Dataset de fine-tuning: passagem → verbete(s) temático(s). Dataset ⏱ ~5 min
Objetivo: empacotar a concordância como exemplos de treino, para uma IA aprender a atribuir verbetes temáticos a uma passagem. Opcional — pule se não vai treinar modelos.
Comando
synesis compile nave.synp --alpaca exports/nave_alpaca.jsonl
Estrutura de cada linha JSONL
{ "instruction": "Which concepts are attributed to the following passage? (Verbete principal do Nave's Topical Bible)", "input": "", "output": "AARON" }
Como interpretar o formato Alpaca
CampoConteúdo
instructionTarefa derivada do DESCRIPTION do campo CODE (entry) — pede os verbetes da passagem
inputVem do campo QUOTATION. Este template não tem QUOTATION populada, então fica vazio
outputO(s) verbete(s) atribuído(s) — a resposta esperada do modelo
Por que input vazio? O Nave indexa referências de passagem, não o texto do versículo. Para um dataset mais rico, você poderia popular o input com o texto bíblico da passage a partir de uma tradução de domínio público.
Inspecionar o arquivo gerado
# Contar pares e ver o primeiro: python -c "import json; L=[json.loads(l) for l in open('exports/nave_alpaca.jsonl', encoding='utf-8')]; print(len(L),'pares Alpaca'); print(json.dumps(L[0], indent=2, ensure_ascii=False))"
Pronto quando: o script imprime 29018 pares Alpaca (passagens agrupadas) e mostra um par com instruction e output preenchidos.

05 Synesis-Coder Codificação assistida por LLM: indexa novas passagens seguindo o template do projeto. Avançado ⏱ ~10 min
Objetivo: acelerar a indexação de novas passagens — a IA lê o template e propõe blocos ITEM (com verbete, subtópico e referência cruzada) que você revisa, em vez de escrever do zero.
Pré-requisito: chave da API
# Opção A — variável de sessão (PowerShell): $env:ANTHROPIC_API_KEY = "sk-ant-..." # Opção B — arquivo .env (recomendado, persiste): ANTHROPIC_API_KEY=sk-ant-... SYNESIS_CODER_MODEL=claude-sonnet-4-6 SYNESIS_CODER_LANGUAGE=en
Onde colocar o .env: na pasta do projeto ou em qualquer pasta-pai de onde você roda o comando — o Coder procura no diretório atual e sobe a árvore. Use o .env.example de synesis-coder/ como modelo. Nunca versione o .env.
Indexar uma passagem (item)
# item: gera um bloco ITEM para a passagem synesis-coder item --project nave.synp --bibref nave1905 --text "Pro 3:5-6 — Trust in the Lord with all your heart." --language en
O Coder lê o nave.synt e gera um ITEM com entry, passage e note sugeridos para você revisar e colar no arquivo da inicial correspondente.
Outros subcomandos relevantes
SubcomandoUso neste projeto
document Indexa um capítulo ou bloco de passagens de uma vez e gera um .syn completo
ontology Lê as anotações e sugere blocos ONTOLOGY (com description) para verbetes ainda não definidos
critique Revisa um arquivo .syn e aponta verbetes mal atribuídos, subtópicos inconsistentes ou xref quebradas
normalize Harmoniza a grafia dos verbetes em arquivos .synr antes de incorporar
incorporate Incorpora um .synr revisado ao arquivo .syn definitivo
Indexar um bloco de passagens (document)
synesis-coder document --project nave.synp --bibref nave1905 --input passagens/proverbios_3.txt --output annotations/nave_T_novos.syn --language en
Fluxo recomendado: document → critique → normalize → incorporate → synesis check. Nunca incorpore sem verificar.
🛟 Solução de problemas — os tropeços mais comuns
command not found: synesis O pacote não está instalado ou o ambiente virtual não está ativo. Rode pip install synesis e confirme com synesis --version.
WARNING — descrições idênticas Avisos como "Conceitos AMAL e ZOPHAH têm descrições idênticas" são esperados (homônimos bíblicos breves). Não bloqueiam a compilação.
E004 — código não definido Um ITEM usa um entry sem bloco ONTOLOGY em nave.syno. Adicione o verbete (ou use o Coder ontology).
E020 — campo REQUIRED ausente Todo ITEM precisa de entry. O erro aponta o arquivo (ex.: nave_M.syn) e a linha.
KeyError: 'code' (em Pandas) A coluna de verbete da tabela ontologies chama-se entry, não code. Use set_index("entry").
Excel abre lento / trava A aba items tem 82 mil linhas. Para explorar, prefira --csv + Pandas em vez de abrir o .xlsx inteiro.
Regra de ouro: a qualquer momento em dúvida, volte ao passo 1 — synesis check é seu paraquedas. Quase todo erro adiante começa como um aviso ignorado aqui.
