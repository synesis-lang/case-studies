O que você vai construir

Este projeto aplica Causation Coding (Saldaña, 2013) a relatos de estudantes sobre como o treino de oratória os transformou. O objetivo é transformar falas soltas em uma rede causal navegável — quem causa o quê, o que apenas habilita, o que reforça ou bloqueia.

"O que, na experiência com oratória, leva a quais resultados — e por meio de que mecanismo?"

Você partirá de 5 arquivos de texto e chegará a tabelas, um grafo causal colorido e, opcionalmente, um banco de grafos consultável e um dataset para treinar uma IA.

Como os 7 passos se encadeiam
5 arquivos → ① checa erros
→ ② JSON (fonte de verdade)
↓ deriva ③ tabelas · ④ dataset IA
→ ⑤ notebook = análise visual
→ ⑥ Coder codifica novos textos
→ ⑦ Neo4j = grafo consultável
Comece pelo essencial: passos 1 → 2 → 3 já entregam o resultado central. Os demais são extensões — faça-os quando precisar.
⚙ Antes de começar — instale e confira
  • Python 3.10+ instalado (python --version)
  • Synesis: pip install synesis · teste com synesis --version
  • Para o notebook (passo 5): pip install pandas matplotlib networkx
  • Para o Coder (passo 6): chave ANTHROPIC_API_KEY
  • Para o Neo4j (passo 7): Neo4j Desktop (neo4j.com/download) rodando + pip install neo4j
  • Terminal aberto na pasta do projeto (onde está project.synp)
📖 Vocabulário mínimo — leia uma vez
ITEM
Uma unidade de análise: um trecho de fala já codificado (citação + resumo + cadeia causal + categoria).
CHAIN (cadeia)
A sequência causal: A → RELAÇÃO → B → RELAÇÃO → C. O coração do método.
papel
Função de um conceito na cadeia: antecedente (causa inicial), mediador (elo intermediário) ou resultado (efeito final).
ontologia
O dicionário de conceitos do projeto — cada conceito definido uma vez, com seu papel e grupo.
bibref
O identificador de cada participante (a "chave" que liga falas a pessoas).

01 Verificar o projeto Confirme que os arquivos compilam sem erros antes de exportar. Essencial ⏱ ~2 min
Objetivo: garantir que os 5 arquivos estão íntegros. Tudo depois disto assume um projeto sem erros — começar aqui evita horas de depuração adiante.
Comando
# A partir da pasta do projeto: cd case-studies/Education/Causation_Coding_Oratoria synesis check project.synp
Saída esperada: ✓ No errors found. — zero ERROs. Avisos não bloqueiam a compilação mas devem ser investigados.
Pronto quando: o terminal mostra No errors found. Se aparecer um código E0xx, veja a faixa de Solução de problemas no rodapé antes de seguir.
Estrutura do projeto
project.synpPonto de entrada: declara template, bibliography, annotations, ontology
template.syntDefine campos, tipos e GUIDELINES para todos os blocos
references.bib8 participantes fictícios em formato BibTeX
annotations.syn16 ITEMs com citações, resumos, cadeias CHAIN e categorias
ontology.syno39 conceitos com papel (antecedente / mediador / resultado) e grupo
Erros comuns: código não definido na ontologia (E004), campo REQUIRED ausente (E020), CHAIN sem ARITY (E047). Execute synesis check para listar todos com número e local exato.

03 Exportar CSV e Excel Gera tabelas prontas para análise em Pandas, R ou planilhas. Essencial ⏱ ~5 min
Objetivo: obter tabelas que você consegue abrir no Excel ou no Pandas para conferir, filtrar e contar os dados codificados. É aqui que o projeto vira algo que você "vê".
Comandos
# CSV: uma pasta com várias tabelas synesis compile project.synp --csv exports/csv/ # Excel: uma planilha com abas separadas synesis compile project.synp --xls exports/causation_oratoria.xlsx # Tudo numa única execução: synesis compile project.synp --json exports/causation_coding_oratoria.json --csv exports/csv/ --xls exports/causation_oratoria.xlsx
Tabelas geradas e suas colunas
TabelaColunas principais
sourcesbibref, perfil, contexto
itemsbibref, citação, resumo, chain, categoria_resultado
ontologies chain (= conceito), descrição, papel, grupo
chainsbibref, from_code, relation, to_code
Atenção: na tabela ontologies, a coluna que identifica o conceito é nomeada chain (o campo CHAIN do template), não code. Use ontologia.set_index("chain") em Pandas.
Leitura via API Python

Pronto quando: a planilha abre com 4 abas (sources, items, ontologies, chains) e a aba chains tem 32 linhas. Parabéns — você concluiu a trilha essencial.

04 Exportar Alpaca JSONL Dataset de fine-tuning derivado dos dados validados pelo compilador. Análise ⏱ ~5 min
Objetivo: empacotar seu trabalho de codificação como exemplos de treino, para que uma IA aprenda a codificar novos trechos do seu jeito. Opcional — pule se não vai treinar modelos.
Comando
synesis compile project.synp --alpaca exports/causation_oratoria_alpaca.jsonl
Estrutura de cada linha JSONL
{ "instruction": "Analise o seguinte trecho e codifique as atribuições causais identificadas, seguindo o método Causation Coding (Saldaña, 2013). Forneça: (1) um resumo analítico do mecanismo causal, (2) a cadeia causal no formato Antecedente -> RELAÇÃO -> Mediador -> RELAÇÃO -> Resultado, e (3) a categoria do resultado principal.", "input": "Os exercícios de improviso me ensinaram a pensar rápido, e isso depois ajudou muito nas entrevistas de emprego.", "output": "resumo: O treinamento de oratória desenvolveu rapidez de raciocínio com aplicação profissional posterior.\nchain: Treinamento_Oratoria -> HABILITA -> Pensamento_Rapido -> HABILITA -> Habilidades_Entrevista\ncategoria_resultado: preparação_profissional" }
Como interpretar o formato Alpaca
CampoConteúdo
instructionTarefa derivada do DESCRIPTION e GUIDELINES do template — explica o método ao modelo
inputValor do campo QUOTATION (citação do participante)
outputValores dos campos MEMO + CHAIN + ENUMERATED — a resposta esperada do modelo
Para que serve: cada linha treina um LLM a replicar o raciocínio do pesquisador — dado um trecho novo, o modelo aprende a produzir resumo analítico, cadeia causal e categoria de resultado no estilo validado pelo compilador.
Inspecionar o arquivo gerado
# Contar pares e ver o primeiro: python -c " import json linhas = [json.loads(l) for l in open('exports/causation_oratoria_alpaca.jsonl')] print(f'{len(linhas)} pares Alpaca') print(json.dumps(linhas[0], indent=2, ensure_ascii=False)) "
Requisito: o compilador só gera o Alpaca se zero ERROs existirem. Use synesis check primeiro.
Pronto quando: o script de inspeção imprime 16 pares Alpaca e mostra um par com os três campos preenchidos.

06 Synesis-Coder Codificação assistida por LLM: anota novos textos seguindo o template do projeto. Avançado ⏱ ~10 min
Objetivo: acelerar a codificação de novos participantes — a IA lê o template (com as GUIDELINES) e propõe blocos ITEM que você revisa, em vez de escrever do zero.
Pré-requisito: chave da API
# Opção A — variável de sessão (PowerShell): $env:ANTHROPIC_API_KEY = "sk-ant-..." # Opção B — arquivo .env (recomendado, persiste): # conteúdo do arquivo: ANTHROPIC_API_KEY=sk-ant-... SYNESIS_CODER_MODEL=claude-sonnet-4-6 SYNESIS_CODER_LANGUAGE=pt-BR
Onde colocar o .env: na pasta do projeto (case-studies/Education/Causation_Coding_Oratoria/) ou em qualquer pasta-pai a partir da qual você roda o comando — o Coder procura no diretório atual e sobe a árvore. Use o .env.example de synesis-coder/ como modelo. Nunca versione o .env (já está no .gitignore).
Codificar um trecho único
# item: anota um trecho de texto diretamente synesis-coder item --project project.synp --bibref participante09 --text "Aprender a debater me ensinou a ouvir antes de responder, e isso mudou minha forma de liderar equipes." --language pt-BR
O Coder lê o template.synt (incluindo GUIDELINES) e gera um bloco ITEM completo para colar em annotations.syn.
Outros subcomandos relevantes
SubcomandoUso neste projeto
document Codifica um arquivo de texto longo (transcrição de entrevista inteira) e gera um .syn completo
ontology Lê as anotações existentes e sugere novos blocos ONTOLOGY para conceitos ainda não definidos em ontology.syno
critique Revisa annotations.syn e aponta itens com cadeias inconsistentes, categorias incorretas ou resumos genéricos
suggest Sugere novos ITEMs a partir de um texto sem codificação anterior
normalize Harmoniza grafia de conceitos em arquivos .synr antes de incorporar ao projeto
incorporate Incorpora um .synr revisado ao arquivo .syn definitivo
Codificar transcrição completa (document)
synesis-coder document --project project.synp --bibref participante09 --input entrevistas/p09_transcricao.txt --output entrevistas/p09_anotacoes.syn --language pt-BR
Expandir ontologia (ontology)
synesis-coder ontology --project project.synp --output ontology_sugestoes.syno --language pt-BR
Fluxo recomendado: document → critique → normalize → incorporate → synesis check. Nunca incorpore sem verificar.
07 Exportar para Neo4j Sincroniza o projeto compilado em memória diretamente no grafo — zero I/O intermediário. Avançado ⏱ ~10 min
Objetivo: levar a rede causal para um banco de grafos, onde você faz perguntas complexas em Cypher ("quais caminhos levam a Confiança?") que seriam difíceis em tabelas.
Pré-requisito 1: instalar o Neo4j
Instale o Neo4j Desktop (gratuito) e crie um banco local. Guias oficiais: neo4j.com/download · tutorial de primeiros passos em neo4j.com/docs/operations-manual/current/installation · introdução ao Cypher em neo4j.com/docs/cypher-manual. Deixe o banco rodando antes de executar o comando abaixo.
Pré-requisito 2: config.toml
# Crie/edite o arquivo synesis2neo4j/config.toml # (use o config.toml existente como modelo) [database] host = "bolt://localhost:7687" user = "neo4j" password = "sua_senha" database_name = "causation_oratoria"
Onde fica: o config.toml mora na pasta synesis2neo4j/. Diferente do .env, ele não é descoberto automaticamente — você informa o caminho explicitamente na flag --config (veja o comando). Pode estar em qualquer lugar, desde que o caminho passado esteja correto.
Comando
# A partir da raiz do repositório: python synesis2neo4j/synesis2neo4j.py --project case-studies/Education/Causation_Coding_Oratoria/project.synp --config synesis2neo4j/config.toml
Atomicidade: toda a sincronização ocorre em uma única transação Neo4j. Se qualquer etapa falhar, o grafo permanece no estado anterior.
O que é criado no grafo
Nó / RelaçãoOrigem
:ConceptCada bloco ONTOLOGY → nó com propriedades descrição, papel, grupo
:ItemCada bloco ITEM → nó com citação, resumo, categoria_resultado
:SourceCada bloco SOURCE → nó com bibref, perfil, contexto
CAUSA / HABILITA / AMPLIFICA / ATENUA / RESTRINGERelações entre :Concept derivadas das cadeias CHAIN
Queries Cypher iniciais
// Conceitos com mais conexões de entrada: MATCH (a)-[r]->(b:Concept) RETURN b.concept, count(r) AS grau ORDER BY grau DESC LIMIT 10 // Todos os caminhos causais até Confianca: MATCH p = (a)-[*1..3]->(b:Concept {concept: "Confianca"}) RETURN p // Triplas por tipo de relação: MATCH (a)-[r]->(b) RETURN type(r), count(r) ORDER BY count(r) DESC
GDS (opcional): se o plugin Neo4j Graph Data Science estiver instalado, o script calcula automaticamente PageRank, Betweenness e comunidades Louvain após a sincronização.
◉ Explorar o grafo HTML Visualização interativa gerada pelo synesis2neo4j — arquivo único, sem servidor. Avançado ⏱ ~5 min
Objetivo: navegar pela rede causal diretamente no navegador — sem instalar Neo4j, sem banco de dados. O HTML gerado é autossuficiente e pode ser partilhado como um único arquivo.
Gerar o grafo
# A partir da raiz do repositório: python synesis2neo4j/synesis2graph.py \ --json case-studies/Education/Causation_Coding_Oratoria/exports/causation_coding_oratoria.json \ --backend html \ --html-output synesis2neo4j/graphs/causation_coding_oratoria.html \ --html-all # Abrir no navegador padrão: start synesis2neo4j/graphs/causation_coding_oratoria.html
--html-all exibe todos os 39 conceitos e 31 arestas, sem filtros de frequência. Para projetos maiores, omita a flag e ajuste --html-min-frequency e --html-min-source-count para focar no núcleo mais citado.
Pronto quando: o navegador abre mostrando os nós coloridos por papel (azul = antecedente, laranja = mediador, vermelho = resultado) e as arestas entre eles.
O que você pode fazer no grafo
AçãoComo

Dois modos complementares: Ontologia agrupa as relações causais em arestas únicas por par de conceitos — ideal para ver a estrutura geral. Evidência expande cada aresta em ocorrências individuais com citação — ideal para auditar a codificação.
🛟 Solução de problemas — os tropeços mais comuns
command not found: synesis O pacote não está instalado ou o ambiente virtual não está ativo. Rode pip install synesis e confirme com synesis --version.
E004 — código não definido Uma cadeia CHAIN usa um conceito que não existe em ontology.syno. Adicione o bloco ONTOLOGY (ou use o Coder ontology no passo 6).
E020 — campo REQUIRED ausente Um ITEM está sem um campo obrigatório do template. O erro aponta o arquivo e a linha exatos.
KeyError: 'code' (no notebook) A coluna de conceito da tabela ontologies chama-se chain, não code. Use set_index("chain"). Veja o aviso no passo 3.
KeyError: 'item_id' (no notebook) As tabelas não têm item_id. A chave que liga itens a cadeias é bibref — junte por ela.
Alpaca não foi gerado O export só ocorre com zero ERROs. Volte ao passo 1 e rode synesis check até zerar.
Neo4j: Connection refused O banco não está rodando ou a porta/senha no config.toml estão erradas. Inicie o Neo4j Desktop e confira host e password.
Regra de ouro: a qualquer momento em dúvida, volte ao passo 1 — synesis check é seu paraquedas. Quase todo erro adiante começa como um aviso ignorado aqui.
